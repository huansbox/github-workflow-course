💡 這門課的藍本

靈感來自一位擅用 GitHub workflow 的腫瘤科醫師（htlin222）的心法： 「Issue 就是待辦事項，完成就是 PR，Merge 會觸發自動化的就用 CI/CD，定期任務用排程。」 課程中的真實案例（auto-merge 防護、cron 自動出刊、自動 release）都取自他的公開 repo，並對照你自己的 handoff / grill-me / to-issues 工作流給出落地建議。

第 1 章 · GitHub Flow：把你已會的串成一套心法

  1. 01github-flow一條 main、短命 branch、merge 即自動化的完整循環
  2. 02issueIssue 當待辦與計畫審核點：task list、label、template、closing keywords
  3. 03pull-requestDraft PR、review、把截圖與驗證放進 PR——讓 PR 成為審核介面
  4. 04merge-strategymerge / squash / rebase 三種合併的取捨，與刪 branch 的坑

第 2 章 · 低頻但高價值：依你的統計補課

  1. 05rebase重放 commit、interactive rebase、force-with-lease 與共享 branch 金律
  2. 06tagannotated vs lightweight、語意化版本、tag 不會自己被 push
  3. 07releasegh release 與自動 changelog——醫生的「自動上版 Beta」
  4. 08auto-mergechecks 綠了自動合併：--auto、branch protection、無人值守的防護清單

第 3 章 · GitHub Actions：你的最大缺口

  1. 09workflowActions 解剖：workflow / job / step / runner / action，逐行讀懂 YAML
  2. 10triggeron: push / schedule / workflow_dispatch / workflow_run 與觸發抑制的坑
  3. 11permissions-secretsGITHUB_TOKEN、最小權限、secrets 與 fork PR 的攻擊面
  4. 12ci-cd串起全流程：CI 檢查 → auto-merge → 部署 → release，加上除錯指令

怎麼使用這門課

  • 順序讀最順（後面單元會引用前面的概念），但每單元自成一體，跳讀也行。
  • 測驗題刻意出得刁：考「何時用」「怎麼用」「會踩什麼坑」，不是名詞背誦。答錯就讀每個選項的解析。
  • 讀完有回饋（太簡單、想加單元、有錯誤）→ 在這個 repo 開 issue。這本身就是第 2 單元的實踐。
