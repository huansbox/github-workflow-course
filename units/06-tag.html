tag

給某個 commit 一個永遠不動的名字。branch 會前進，tag 釘在原地——這正是「版本」需要的性質。

📊 你的數據 git tag 在你的紀錄只出現 10 次——幾乎沒用過。這很合理：你的專案多是「持續演進、隨時最新」的型態， 沒有發版需求就沒有 tag 需求。但下一單元的 Release（醫生的「自動上版」）整個建立在 tag 之上， 而且 tag 有一個違反直覺的行為（不會跟著 push 走）值得先知道。

這是什麼

tag 是指向單一 commit 的固定指標。與 branch 的差別一句話：branch 是會移動的書籤，tag 是釘死的圖釘。 commit 之後 branch 自動前進，tag 永遠停在原地。

兩種 tag：

LightweightAnnotated
建立git tag v1.0.0git tag -a v1.0.0 -m "訊息"
本體只是一個指標完整物件：作者、日期、訊息、可簽章
用途私人暫時標記發版一律用這個——「誰在何時發了這版」是 metadata 不是猜測

語意化版本（SemVer）

tag 名慣例用 v主.次.修（如 v2.1.3）：

  • MAJOR：不相容的改動（使用者要改東西才能升級）。
  • MINOR：新增功能，向下相容。
  • PATCH：修 bug，向下相容。
  • 預發行版接後綴：v2.0.0-beta.1——醫生的「自動上版 (Beta)」就是這類 prerelease 版號。

單人專案不必教條化——SemVer 的真正價值是對使用者的溝通契約。沒有外部使用者的工具， 用 v1、v2 或日期版號（v2026.08.13）都行，重點是一致。

怎麼用

# 建立 annotated tag（打在目前 HEAD）
git tag -a v1.0.0 -m "第一個公開版"

# 補打在歷史 commit 上
git tag -a v0.9.0 -m "..." abc1234

# 查看
git tag                  # 列出全部
git show v1.0.0          # tag 詳情＋指向的 commit

# 推上遠端 —— tag 不會隨 git push 自動上傳！
git push origin v1.0.0   # 推單一 tag（推薦）
git push --tags          # 推全部 tag（小心把實驗性 tag 也推上去）

# 刪除
git tag -d v1.0.0                  # 本地
git push origin --delete v1.0.0    # 遠端

# 回到某版的狀態看看
git switch --detach v1.0.0

常見的坑

  • git push 不會推 tag：這是最常見的意外。本地打了 tag、push、然後遠端什麼都沒有——tag 要顯式推（git push origin v1.0.0）。反過來 git fetch 預設會抓 tag，所以「拿得到別人的、自己的上不去」這種不對稱很困惑人。
  • 移動已發布的 tag 是反模式：tag 的價值就是不動。發現 v1.0.0 打錯 commit，正確做法是發 v1.0.1，不是刪掉重打——別人可能已經拿著舊 v1.0.0 在跑了（Git 也不會自動更新別人已抓到的 tag）。
  • checkout tag 進入 detached HEAD：在上面 commit 的話，那些 commit 不屬於任何 branch，switch 走就「消失」（reflog 找得回）。要基於舊版開發：git switch -c hotfix-1.0 v1.0.0。
  • 發版用 lightweight tag：少了日期、作者、訊息，日後考古只能對著一個裸指標猜。發版一律 -a。
💡 何時值得開始打 tag 你目前「repo 即最新版」的模式下，兩個訊號出現時 tag 開始有價值： ① 有東西依賴你的特定版本（例如 my-run 的某版被排程任務用著，你想繼續開發又不想弄壞它）； ② 你想要「回到上次好的狀態」有個人類可讀的名字，而不是翻 commit hash。 第 7 單元會看到：打 tag 這個動作本身可以觸發自動化（on: push: tags）。

✅ Takeaways

  • branch 會動、tag 不動；「版本」需要的正是不動。
  • 發版用 annotated tag（-a -m），metadata 齊全。
  • git push 不帶 tag——要 git push origin v1.0.0 顯式推。
  • 打錯版就發新版號，永遠不要移動已發布的 tag。
  • SemVer 是對使用者的溝通契約：MAJOR 破壞相容、MINOR 加功能、PATCH 修 bug。
