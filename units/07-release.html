release

Release = tag + 人話說明 + 附件下載區。醫生那句「合併後自動上版 (Beta)、自動合成 Changelog」的主角就是它。

📊 你的數據 gh release 出現 11 次，接近零。你的專案目前用「main 即最新版」的模式運作，沒有 release 也活得很好—— 所以這一課的重點不是「你該天天發版」，而是搞懂 release 機制與 changelog 自動合成的原理： 它會回頭改變你寫 PR 標題的方式。

這是什麼

Release 是 GitHub 在 tag 之上加的一層發布物：

  • 基底是 tag：每個 release 綁定一個 tag（可以指向既有 tag，或發布時順便建 tag）。
  • Release notes：這一版改了什麼，Markdown 自由發揮——或自動生成（下述）。
  • Assets：可掛任意檔案（執行檔、zip、PDF……）。醫生的 vox-styled-reels 把每張教學卡片渲染成影片後，就是以「一卡一 release」的形式把 mp4 掛在 assets 上。
  • 狀態旗標：--draft（草稿，只有自己看得到）、--prerelease（標示為預發行——醫生的「Beta」）。

怎麼用

# 最常用的一行：建 tag + release + 自動生成 notes
gh release create v1.2.0 --generate-notes

# Beta 版（prerelease 標記，不會成為 "Latest"）
gh release create v1.2.0-beta.1 --generate-notes --prerelease

# 掛附件
gh release create v1.2.0 dist/app.zip report.pdf --generate-notes

# 草稿先看再發
gh release create v1.2.0 --generate-notes --draft

# 查看與下載
gh release list
gh release view v1.2.0
gh release download v1.2.0

自動 changelog 的原理

--generate-notes 不是魔法：它抓上一個 release 到這次 tag 之間所有合併的 PR 標題， 列成清單、附上 PR 連結與作者。所以——

  • PR 標題寫得好（你的 Conventional Commits 習慣：feat: ...、fix: ...），changelog 就自動可讀。
  • 在 repo 放 .github/release.yml，可以依 label 把 PR 分類成段落（Features / Bug fixes / …），或排除特定 label（如 dependencies）。
  • 直接 push 進 main、沒走 PR 的 commit 不會出現在自動 notes 裡——又一個「一律走 PR」的理由。

這就是醫生流程「Merge 後自動合成 Changelog」的機制核心；配上第 3 章的 Actions（merge 觸發 workflow 執行 gh release create），就是全自動上版。

常見的坑

  • notes 品質 = PR 標題品質：changelog 難看不是工具問題，是「fix stuff」式標題的問題。垃圾進垃圾出。
  • prerelease 不擋人：--prerelease 只是標籤（不會列為 Latest），任何人仍能下載。它是溝通工具，不是存取控制。
  • release 一發即公告：發布會通知 repo 的 watcher、出現在 feed。沒把握就先 --draft，看過再轉正式。
  • 刪 release 不會刪 tag：兩層是分開的。刪錯了要兩邊都清（gh release delete + git push origin --delete <tag>）。
  • 大檔案塞 repo 而不是 assets：建置產物（zip、影片、執行檔）commit 進 repo 會永久肥大歷史；掛在 release assets 上 repo 保持乾淨——醫生的影片放 assets 而不是 repo，就是這個原因。
💡 給你的優化建議 最快能受益的場景：dotfiles-claude。skills 改壞時你需要「回到上次好用的狀態」—— 每次大改後 gh release create v2026.08.13 --generate-notes，一行指令就有帶人話說明的還原點， 比翻 commit log 找「哪一版還是好的」快得多。日期版號即可，不必套 SemVer。

✅ Takeaways

  • Release = tag + notes + assets；tag 是身分，release 是發布物。
  • gh release create vX --generate-notes 一行完成 tag + release + changelog。
  • 自動 notes 來自兩個 release 之間合併的 PR 標題——PR 標題就是未來的 changelog。
  • --prerelease 是標籤不是門禁；--draft 才是「先不公開」。
  • 建置產物掛 assets，不要 commit 進 repo。
